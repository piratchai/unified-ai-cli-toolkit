# OpenCode (`opencode`) - Complete Feature Reference

Official Documentation: [OpenCode Documentation](https://opencode.ai/v2/docs/)

| Feature / Command | Documentation Link | How It Works & Configuration | How to Use (Syntax / Config) | Concrete Real-World Use Case |
| :--- | :--- | :--- | :--- | :--- |
| **Full-Screen TUI** | [Interactive TUI](https://opencode.ai/v2/docs/cli/#tui) | Terminal user interface with split panes, real-time syntax highlighting, and keyboard navigation. | `opencode` | Focused, terminal-native pair programming directly in your shell. |
| **`opencode mini`** | [Mini Mode](https://opencode.ai/v2/docs/cli/#mini-mode) | Compact terminal HUD overlay designed to occupy minimal screen space. | `opencode mini` | Running OpenCode alongside an active Neovim buffer in a split terminal pane. |
| **Headless `opencode run`** | [Headless Runner](https://opencode.ai/v2/docs/cli/#headless-mode) | Programmatic non-interactive CLI runner returning standard Unix exit codes. | `opencode run "Fix ESLint errors in src/"` | Running unattended code refactors, pull request audits, and migrations in CI/CD. |
| **`opencode service`** | [Daemon Architecture](https://opencode.ai/v2/docs/cli/#service-daemon) | Background service backed by a shared SQLite database managing sessions across terminals. | `opencode service start` | Seamlessly switching between multiple terminal windows sharing state across microservices. |
| **`--standalone`** | [Standalone Flag](https://opencode.ai/v2/docs/cli/#standalone) | Bypasses background daemon and runs strictly inside the current terminal process. | `opencode --standalone` | Running clean, sandboxed tasks inside Docker containers or ephemeral CI environments. |
| **`--server <url>`** | [Remote Server](https://opencode.ai/v2/docs/cli/#remote-server) | Connects local OpenCode CLI to a remote headless OpenCode daemon over WebSocket/HTTP. | `opencode --server https://devbox.internal:4040` | Driving a powerful remote development server from a lightweight laptop. |
| **`build` Agent** | [Build Persona](https://opencode.ai/v2/docs/agents/#build-agent) | Primary full-access software engineering persona with full file, shell, and tool capabilities. | Default persona in TUI | General software engineering: writing features, refactoring modules, fixing tests. |
| **`plan` Agent** | [Plan Persona](https://opencode.ai/v2/docs/agents/#plan-agent) | System architecture persona. Strictly read-only on repository source code, outputting plans. | Select `plan` agent via TUI | Designing technical specifications and database schemas before writing code. |
| **`explore` Agent** | [Explore Persona](https://opencode.ai/v2/docs/agents/#explore-agent) | Read-only codebase explorer persona optimized for deep semantic searches and symbol discovery. | Select `explore` agent via TUI | Safely browsing and indexing unfamiliar open-source codebases. |
| **Custom Markdown Agents** | [Custom Personas](https://opencode.ai/v2/docs/agents/#custom-agents) | Define custom agent personas using Markdown files with YAML frontmatter specifying tools and perms. | `.opencode/agents/security.md` | Creating specialized roles such as Security Auditor, Database Admin, or QA Engineer. |
| **Custom Markdown Commands** | [Custom Commands](https://opencode.ai/v2/docs/commands/#markdown-commands) | Define custom slash commands using Markdown files with `$ARGUMENTS` interpolation. | `.opencode/commands/test.md` | Standardizing complex team workflows into simple shortcuts like `/test-unit`. |
| **Fine-Grained Permissions** | [Permissions Engine](https://opencode.ai/v2/docs/permissions/) | 3-tier security model configured per action (`read`,`write`,`execute`), resource, and effect. | In `opencode.jsonc`: `{"permissions": [...]}` | Preventing the agent from touching sensitive files (secrets, `.env`) or dangerous bash commands. |
| **Git Snapshot Engine** | [Checkpoints](https://opencode.ai/v2/docs/cli/#snapshots) | Automatic Git-based checkpointing of files before tool executions, allowing instant rollback. | Automatic in runtime | Recovering instantly if an agent proposes broken code that corrupts your working tree. |
